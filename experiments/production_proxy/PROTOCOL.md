# 生产场景代理评测 v2：构建前约定

目标不是降低分数，而是检验有效范围。不预设混合检索必须胜出。
本目录与上一轮实验分开，不覆盖旧语料、旧结果或原业务代码。

1. 使用公开完整报告的文本导出；保留来源、原始页/记录、文档 ID 与字符位置。
   OCR 导出不等同于原 PDF 视觉版，完整性与结构损失必须披露。
2. 目标 200–300 条问题。常规业务模拟与边界挑战分开汇总；
   不声称比例来自客户查询日志，不冒充专家金标。
3. 正常问题、同义表达、特定对象、跨段证据、版本/时间、权限、无答案与澄清分别标识。
   合成文档明确标识且与公开真实报告单列结果。
4. 问题与证据标注在观察检索结果前冻结。证据使用稳定源文档位置，
   分块变化后按原文位置判覆盖，不要求新旧 chunk ID 一致。
5. 开发与测试按来源文档/系列分组，相关改写留在同组。
   以前看过的 DISKOS-QA 问题不充当新的未见测试问题。
6. 保留长片段截断基线，同时增加每块不超过模型 token 上限的向量基线。
   BM25 与混合检索使用相同适配分块；固定模型、候选预算和融合参数。
7. 区分检索证据覆盖、排序、权限/版本错误、无答案与澄清；
   不把无答案题放进普通召回分母。
8. 有限 API 额度优先用于统一的小型重排对照；全部题目的本地召回评测必须完成。
   若未运行回答生成，不得报告答案正确率或生成拒答率。
9. 额外候选池审阅不能悄悄改变冻结主标签；若发现标签遗漏，
   单列审阅记录和修订版本，保留原结果。
10. 报告失败案例、题目相关性、小样本/模板偏差、OCR 局限与复现条件。
